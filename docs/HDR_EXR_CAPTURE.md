# Genuine scene-linear HDR / OpenEXR capture

The **Capture linear EXR** command is separate from existing SDR PNG capture. It is supported only when Godot can provide actual floating-point **3D scene-color pixels before tonemapping**, and never obtains those pixels by converting an SDR screenshot to floating-point.

## Renderer path and synchronization

On Forward+ or Mobile with a valid global `RenderingDevice`, Godauldron temporarily attaches a `CompositorEffect` to the current experiment-owned `Camera3D`. Existing camera compositor effects—or the inherited scene `WorldEnvironment.compositor` effects when there is no camera compositor—remain in their original order; no provider compositor resources are modified. The host effect is appended to a **temporary** compositor and removed after the request; the original camera compositor is restored only if Godauldron still owns the temporary attachment.

The compositor callback runs at `EFFECT_CALLBACK_TYPE_POST_TRANSPARENT`, after opaque/sky/transparency but **before built-in postprocessing/tonemapping**. It accesses the engine's resolved `render_buffers/color` texture through `RenderSceneBuffersRD`. It requires mono view, bounded dimensions and an actual `RGBA16F` or `RGBA32F` scene-color texture. **When the renderer does not mark that texture CPU-copyable**, a small compute shader reads exact scene-linear texels through its sampled-image usage into a new, host-owned float texture with `TEXTURE_USAGE_CAN_COPY_FROM_BIT`; the destination keeps the original 16/32-bit channel format. An asynchronous `RenderingDevice.texture_get_data_async()` then retrieves that buffer without blocking `texture_get_data()` on the rendering thread. If neither copying nor shader sampling is supported, the request **fails explicitly**; no displayed LDR viewport fallback is permitted.

Results arrive through a thread-safe one-shot mailbox and are decoded into `Image.FORMAT_RGBAH` or `FORMAT_RGBAF` without SDR conversion or tone mapping. Output is an **OpenEXR** file and a JSON provenance sidecar. EXR output does not clip pixel values to 1.0. It retains values greater than 1 and negative floating channel values when present; the output is **not** a display-referred PNG in an EXR wrapper.

Readback is explicitly outside measured benchmarks, campaigns, image comparison and other captures. When started during interactive playback, the host pauses fixed-step progression, clears its playback accumulator, resolves any active authored camera track at the frozen absolute step and snapshots the camera/timeline/graphics/Environment provenance **before** the asynchronous compositor request. The captured EXR metadata describes that frozen source state, not the step reached by the time file encoding finishes. The host reserves the capture lifecycle before installing the compositor. A bounded render-frame timeout and scene/camera ownership checks prevent misattributing a buffer to a different experiment. The host records renderer, engine, active camera path, graphics settings and effective Environment provenance. It does not claim GPU or CPU timings for this operation.

## Precision and limitations

This records Godot's own **scene-linear renderer color at the selected compositor stage**. It is not a physical radiance calibration or guaranteed whole-frame HDR display output; built-in glow, exposure/tonemapping, color correction and later postprocessing are intentionally absent. The image dimensions are the **internal 3D render dimensions**, which may differ from the displayed viewport under scaling, TAA or spatial upscaling. A provider that draws outside Godot's normal render pipeline may not appear in this buffer.

Godot's `CompositorEffect` APIs are experimental, and source buffer copy permissions and asynchronous readback depend on the renderer and driver. Compatibility and headless rendering cannot provide this compositor path. If the active renderer uses another buffer format or disallows copying, the UI reports **unavailable** rather than inventing output.

The headless regression tests the real TinyEXR encoder/decoder and proves a floating-point image with a 12.5-valued highlight and a negative channel round-trips without clipping. It also ensures SDR inputs and unsupported Compositor backends are rejected. A separate **real Forward+ Vulkan integration job** uses Mesa llvmpipe and a deliberately overbright 3D shader, then captures the engine's pre-tonemap scene-color buffer through a same-format GPU compute transfer into a readable floating-point staging texture. The EXR is reopened and its red channel is verified above 2.0 (the recorded initial successful test recovered 14.0), demonstrating the output was not clamped to SDR. The CI test also checks restoration of the provider compositor resources, including inherited WorldEnvironment effects. This proves the renderer capture path on software Vulkan; separate AMD, Intel and discrete GPU hardware validation remains necessary.

## Fixed-step HDR sequences

**Export linear EXR frames** uses the same playback controls as the existing PNG sequence exporter: start step, frame count and playback fixed delta. It shares the validated, crash-recoverable `FrameSequence` manifest writer with PNG rather than implementing another timing lifecycle. The HDR output directory defaults to `user://hdr_sequences`.

After a provider reset and seek, each selected scene-owned camera receives any authored track pose at its **absolute** step index. Godauldron then installs its temporary compositor, waits for an asynchronous real float GPU readback, writes a separate `frame_000000.exr` plus JSON sidecar, restores the provider's camera/inherited compositor ownership, and only then advances to the next fixed step. This serial capture is intentionally unmeasured and favors exact frame identity over throughput. Missing or unsupported GPU source, renderer/camera replacement, invalid dimensions, and encoder failures stop the sequence with an explicit error instead of silently substituting an SDR image.

The manifest records `capture_type=fixed_step_scene_linear_exr_sequence`, first-frame render-buffer size and source, requested/written frame counts, source timebase, and full authored camera track. Each frame records its own source, dimensions, simulation step, camera transform, effective Environment, graphics settings and provider state. As with PNG, the manifest is updated after **each successfully committed frame**, so process interruption leaves an auditable incomplete export.

The software-Vulkan Forward+ CI path now also exports **three real EXR frames at steps 5–7**, verifies floating-point pixels above 1.0, validates keyframed camera positions against those exact step numbers and checks provider compositor restoration after each GPU readback. A separate headless test verifies EXR >1 and negative-value transport, strict SDR rejection and incomplete manifests on missing frames. Hardware vendor compatibility and accelerated batch-readback optimization are not claimed.

## Remaining engineering

GPU queue/resource lifetime validation under hardware stress, normal/depth/velocity/AOV readbacks, EXR multi-part channels, HDR10 display output and engine-native buffer metadata require additional backend validation. These are separate milestones from the floating-point EXR writer and current one-shot scene-color path.
